# Architecture and reproducibility boundaries

> **Scope:** Documentation of the historical AWS EMR/Hive flight-delay analysis and
> the offline checks currently reproducible from this repository. This is **not**
> an infrastructure deployment guide or a claim of independently reproduced ML
> performance.

## Data flow and ownership

```text
Historical 2008 flights CSV (not committed)
  -> header removal: scripts/data_cleaning_commands.sh
  -> AWS S3 staging / EMR primary node (historical, not executed here)
  -> Hive hritik_flights_2008: sql/phase1_hive_analysis.sql
     -> airport delay-hours ranking
     -> carrier delay-hours ranking
     -> arrival vs. departure delay-hours totals
     -> published snapshots: data/2008_*_results.csv
                             data/arrival_departure_delay_comparison.csv

Historical 1995/1997/2004/2008 team samples (not committed)
  -> Hive 2008 sample: sql/phase2_sample_generation.sql
  -> local concatenation/cleaning: scripts/phase2_logistic_regression_template.py
  -> historical logistic regression report and ten labels: data/*.csv
  -> evaluation caveats: docs/model_evaluation_audit.md
```

The Phase 1 Hive queries filter cancelled and diverted flights and sum
**positive** arrival/departure delay minutes, converting minutes to hours by
dividing by 60. Airport totals combine origin departure delay with destination
arrival delay; carrier totals combine both delay types per carrier. The three
published report CSVs are **snapshots**, not outputs regenerated by the offline
test suite.

## What is reproducible without AWS

From the repository root, with Python 3 and no third-party packages:

```bash
python -m unittest discover -s tests -v
```

- `tests/test_published_outputs.py` checks the ten published prediction rows,
  sequential record identifiers, and `Y`/`N` labels.
- `tests/test_published_aggregates.py` checks ordered/unique airport and
  carrier rankings, positive delay totals, arrival/departure reconciliation,
  and arithmetic consistency between the published confusion matrix and
  accuracy/precision.

These are **artifact consistency tests**. They do not execute Hive, reconstruct
the underlying flight records, establish the accuracy of the original
aggregations, or retrain the classifier. A passing result must never be
described as proof of prospective model quality.

## Historical execution requirements (not run automatically)

| Stage | Required input or environment | Reproducible from this checkout? |
| --- | --- | --- |
| CSV preparation | Original `2008.csv` | No; raw file is not committed |
| Hive load and Phase 1 queries | EMR/Hive and cleaned CSV | No; may incur AWS costs |
| Hive Phase 2 sampling | Loaded flights table | No; `RAND()` is unseeded |
| Python Phase 2 training | Four team sample CSVs listed in the training template | No; those samples are absent |
| Published-output checks | Small checked-in CSV snapshots | Yes; offline |

**Do not run** `scripts/data_cleaning_commands.sh` as an unattended script:
it contains illustrative S3 upload, SSH and SCP commands with historical
bucket, key-file and host assumptions. No credentials or PEM files belong in
this repository.

## Idempotence and data-quality limitations

- `LOAD DATA LOCAL INPATH ... INTO TABLE` can append rows when rerun against
  an existing Hive table. A rerun needs an explicit clean-load strategy and
  record-count verification; this repository does not provide one.
- `CREATE TABLE IF NOT EXISTS hritik_sample AS ...` may retain an old sample
  rather than refresh it. `DISTRIBUTE BY RAND() SORT BY RAND()` does not
  document a reproducible sampling seed.
- No raw input checksums, source-row counts, Hive version, EMR configuration,
  or full dependency lockfile are committed. Therefore end-to-end replay and
  output lineage cannot currently be independently verified.
- The Phase 2 target uses `ArrDelay` or `DepDelay` greater than 15 minutes,
  and the training template retains those columns as predictors. It also
  preprocesses before a random split. See
  [model evaluation audit](model_evaluation_audit.md) before interpreting the
  published 99.48% historical accuracy.
